What this experiment is actually testing

Not another chatbot. Not one-shot vibe coding.

The core hypothesis:

Reliable software delivery requires a governed evidence layer before any coding agent is allowed to act.

Primary learning focus

Convert messy enterprise information into traceable, approved specifications before coding begins.

Delivery method

Use the traditional 4D lifecycle: Discover, Define, Develop, Test & Deploy.

Enterprise constraint

Prefer open-source and air-gap-compatible components. Use OpenAI only as a personal-lab accelerator.

ENTERPRISE PROJECT INTELLIGENCE WORKSPACE 07 / 33

The core design rule

The LLM interprets evidence. It does not own truth.

Immutable evidence

Never overwrite originals. Preserve file hash, source metadata, versions and extraction history.

Derived interpretation

Summaries, answers and drafted specs remain explainable outputs linked back to evidence.

Approved contract

Only reviewed requirements and specifications become the development baseline.
NON-NEGOTIABLE

New evidence creates a proposed change.

It must never silently rewrite approved requirements or trigger code changes without review.

ENTERPRISE PROJECT INTELLIGENCE WORKSPACE 25 / 33

Minimum governance controls

What prevents a clever prototype from becoming an operational liability

Evidence provenance

Every answer links back to source documents, page, slide, sheet, row or image region.

Access control

Retrieve only evidence the user is allowed to see inside the active project.

Version control

Separate approved, proposed, stale, superseded and conflicting information.

Human approval

No autonomous rewrite of requirements, tests or release criteria.

Observability

Log uploads, extraction, retrieval, prompts, outputs, diffs, approvals and agent actions.

Model validation

Actively smoke-test each model, server, auth route and adapter combination.

Dependency control

Mirror packages and models internally; review licences before import.

Release discipline

Agents propose fixes. CI/CD decides whether a build passes.

ENTERPRISE PROJECT INTELLIGENCE WORKSPACE 30 / 33

Email ingestion needs a separate branch

Docling is the first-pass document parser, not the universal parser

What works now

.eml files are routed through Python's standard-library email parser. The router preserves headers, body text and attachment count.

Known gap

Microsoft Outlook .msg files are not handled in the current learning phase. This is recorded explicitly rather than hidden.

Evaluate later

extract-msg is a possible open-source candidate for Outlook message extraction. Evaluate it after the main evidence-to-OpenSpec learning flow is complete.
LEARNING POINT

Do not force every file through Docling.

Enterprise ingestion should route each format through the right extractor and preserve provenance.

Email remains important because requirements and approvals often appear there before formal documents are updated.
